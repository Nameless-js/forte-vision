# ASSUMPTIONS and non-obvious decisions

Numbered, append-only. Each entry: what was decided, why, and where it matters.

- **A-01 Task document naming.** `FORTE_AI_TASK.md` is the task specification; wherever the spec says `TASK.md` it means this file. The ForteBank ТЗ (`Кейс_ForteBank.docx`) is the source of truth if the two conflict. No conflicts were found on reading both in full (2026-10-17); the ТЗ output schema matches Section 6.1 of the task verbatim.
- **A-02 Platform.** Native Windows 11, no WSL, no `make`, no `docker`, no system `ffmpeg`. Consequences: (a) all Make targets are implemented in `scripts/run.py <target>` and a `Makefile` wrapper delegates to it; (b) decoding uses PyAV (BSD-3, bundles FFmpeg LGPL libs) and re-encoding uses the `imageio-ffmpeg` bundled binary (BSD-2 wrapper around an LGPL FFmpeg build — no GPL components are linked into our code); (c) the offline gate is implemented with `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` + a socket-level guard that raises on any outbound connect during `analyze()` + a static code audit, instead of `unshare -n`; (d) the Dockerfile is provided and reviewed but cannot be built on this host — documented as a limitation. vLLM is Linux-only, so the VLM is served through `transformers`.
- **A-03 Duplicate videos.** `Х-4.mov` and `Х-47.mov` are byte-identical (md5 `fdd5aa51…`), labeled 57 s and 68 s respectively; `Х-5.mov` and `Х-48.mov` are byte-identical (md5 `304e8be8…`), both clean. Decision: keep all 42 label rows for metrics (so recall is still counted over 22 rows and FP over 20 rows, exactly as the gate is phrased), but (i) the duplicated violation video is required to produce events near **both** 57 s and 68 s, and (ii) leave-one-video-out folds are formed by **content hash**, so both rows of a duplicate pair are held out together and never leak into each other's fit. `data/labels.csv` carries a `content_md5` column for this.
- **A-04 Video id matching.** Ids are parsed as the trailing integer of the file stem after stripping the extension; the leading letter (Latin `X` U+0058 or Cyrillic `Х` U+0425) is ignored. Labels and files are joined on the integer id only.
- **A-05 Timestamp parsing.** Free-text timestamps are parsed to float seconds by a tolerant parser (`forte_ai/labels.py`): supports `"22 секунда"`, `"1минута 8 секунда"`, `"1 мин 8 сек"`, `"1:08"`, `"68"`, `"11-я секунда"`, decimal comma. Unit tests cover all label strings present in the file plus edge cases.
- **A-06 Python version.** Python 3.12 is used (3.14 is installed but PyTorch/CUDA wheels and several CV packages do not support it yet). PyTorch 2.6.0 + CUDA 12.4 wheels run on the installed 555.97 driver (CUDA 12.x minor-version compatibility).
- **A-07 Unlabeled split.** Ids 6, 7, 9, 36, 41, 42 exist neither as files nor labels, so the unlabeled split is empty; the code path for it still exists (`split == "unlabeled"`) and is exercised by a unit test with a synthetic file list.
- **A-08 Frame viewing.** `AGENT_MAY_VIEW_FRAMES: true` → development-time frame review of the training videos is done by the agent (contact sheets in `analysis/review/`, gitignored). The shipped service never does this; it never calls external AI.
- **A-09 Dependency versions.** PyAV had no cp312 Windows wheel in the `<15` range at install time, so the pin is `av>=13` (15.1.0 installed). OpenCV 5.0.0.93 (headless) was pulled in by `rtmlib`, together with `opencv-python`/`opencv-contrib-python` of the same version — harmless duplicates, recorded in LICENSES.md. NumPy 2.2.6. Exact versions are frozen in `requirements.txt`.
- **A-10 Video geometry.** All 42 training videos are **464×848 portrait**, h264, ≈29.8–30 fps, no audio, no rotation metadata (PyAV reports none). The engine never assumes this geometry: everything is normalised by frame size, and the robustness suite re-encodes/rescales/rotates.
- **A-11 Timing benchmark videos.** The three longest videos are Х-14 (142.5 s), Х-39 (78.7 s), Х-4 ≡ Х-47 (72.7 s); `make timing` runs on these.
- **A-12 Team taxonomy vs engine types.** The arbitrated team taxonomy (analysis/taxonomy.md, 8 types, skeptic pass agreed on all 22 events) is the ground truth for type accuracy. The engine keeps finer, rule-card-backed ids (e.g. `workplace_left_unsecured`, `cash_left_unattended`, `cashier_left_during_service` → team `workplace_left_unattended`; `no_id_check`, `collection_bag_unchecked` → team `handover_without_documents`; `phone_at_workplace` → team `personal_items_at_workplace`); the mapping lives in `analysis/taxonomy.json:team_of` and is applied only in evaluation.
- **A-13 Person validity.** Grounding DINO returns person boxes up to 0.88 on chairs, jackets and glass reflections, and RTMPose always returns 17 keypoints (hallucinated on non-persons). A track counts as a real person in a frame only if ≥3 of its 6 arm keypoints are confident or its matched detection is ≥0.65; room occupancy additionally needs detection ≥0.55. People behind the glass wall (0.35–0.5) are thus excluded from occupancy/departure logic.
- **A-14 Cashier seat.** The seat is the first stationary dwell (≥3 s within 2.5 % of the diagonal) of the cashier track, not the whole-track median: in short clips the cashier may spend half the video standing at the door, and in this projection the door is as close to the equipment as the seat is.
- **A-15 Layer C design change (measured).** In generative JSON mode Qwen3-VL-2B answered identically for true and false candidates (iter_013 vlm_signal.md: e.g. departures 6 "support" on true vs 5 on false; no key with separability ≥0.5 on ≥3 samples). Layer C was redesigned as contrastive two-statement scoring: P("A") vs P("B") from first-token logits, both option orders averaged (removes position bias), confidence moved by w·(2p−1). Russian descriptions are generated separately, only for reported violations.
- **A-16 Config precedence.** default.yaml < profile overlay < explicit user config (file or dict) < programmatic overrides. (Before the fix a YAML passed with `--config` was silently overridden by the profile overlay.)
- **A-17 Low-confidence, VLM-arbitrated rules.** Patterns that geometry cannot separate from normal behaviour (note merged back after a machine count — video 44 vs clean 43/45; safe left open — video 20; collector bag without document — 17; count started only as the client left — 34; issue long after a counting-like motion) emit candidates at 0.40–0.48, below the verdict threshold, and only cross it when Layer C supports them. On the CPU profile (no VLM) they never fire.
- **A-18 Handover.** A handover is an active reach (wrist ≥10 % of the diagonal ahead of the torso and at/over the counter line), not hand proximity: two people seated across a desk keep their hands within reach all the time.

- **A-12 Completion audit.** `Analyzer.deadline_sec` is a soft budget. Untrusted API uploads use a persistent
  spawned inference process with a separate parent-enforced timeout (270 s by default). A timed-out job is
  failed explicitly. We do not infer a clean verdict from a timeout or unavailable model.
- **A-13 Validation scope.** LOVO holds out content groups for threshold fitting, but rule discovery and prompt
  engineering used all training videos. Reported LOVO numbers are development estimates, not unbiased unseen
  performance. Augmentations do not substitute for an independently filmed camera-angle test.
- **A-14 Shipping profile.** Qwen3-VL-4B-Instruct NF4 with contrastive scoring is the measured GPU-small default.
  Catch-all is experimental and disabled explicitly. CPU mode cannot verify `needs_support` candidates.
