# Подключение модели: восстановление, опровержение и испытания

## Точка подключения

`analyze_video(path: Path)` в `backend/model_adapter.py` подключён к корневому `forte_ai` через
`SupervisedAnalyzer`. Процесс модели сохраняется между заданиями, тайм-аут 250 с принудительно останавливает
его, а следующее задание запускает новый процесс. Веб-сервер сохраняет прогресс через context callback и
отдаёт поля `progress`/`stage`. При закрытии сервера анализ отменяется и процесс освобождается.
Файлы удаляются после завершения/ошибки. Нормативные document/clause отображаются как title/section.
Локальные веса не отправляются в облако, имя файла не используется как метка.

Сохранены обязательные маршруты жюри: `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`, заголовок `X-API-Key`. Два вердикта: `violation` и `no_violation`; пустой список событий при отрицательном результате. Требуются 1–3 настоящих JPEG-доказательства у каждого положительного события. Контекстные кадры интерфейса не заменяют доказательства в API.

## Дополнительные наблюдения `checks`

Каждое событие может содержать массив до четырёх наблюдений:

```json
{
  "id": "action_sequence",
  "status": "confirmed",
  "note": "Наблюдаемая последовательность действий описывается здесь без предположений о невидимых данных.",
  "timestamp_sec": 12.4,
  "translations": {
    "en": "Describe the visible sequence here, without assumptions about unseen data.",
    "kk": "Көрінбейтін деректер туралы жорамалсыз, көрінетін әрекеттер ретін сипаттаңыз."
  }
}
```

Это пример структуры, не реальная детекция.

| Идентификатор | Что проверяется |
|---|---|
| `subject_visible` | Видно участника действия в нужный момент |
| `object_state_visible` | Различимо состояние релевантного объекта |
| `action_sequence` | Видимые действия до/после подтверждают последовательность |
| `alternative_explanation` | Есть видимый контекст, предлагающий альтернативное объяснение |

Статусы: `confirmed`, `refuted`, `unknown`. Отсутствие наблюдения — **unknown**, никогда не подтверждение. У confirmed/refuted обязательна непустая заметка; у всех отметок время, если передано, должно быть конечным неотрицательным числом. Повторяющиеся и неизвестные ID отклоняются сервером. `alternative_explanation=confirmed` требует внимания проверяющего; это не подтверждение нарушения.

Проверки — общий интерфейс наблюдений, а не готовый классификатор или юридические правила. Напарник должен реализовать получение наблюдений из своей модели/локальной логики. Фронтенд не вычисляет их из наличия кадра и не меняет автоматический вердикт. Ручные отметки и комментарий живут в сеансе страницы и в экспортируемом отчёте `human_review`; они не записываются поверх результата модели. Перед закрытием страницы экспортировать отчёт.

## Восстановление события

В рабочей станции выбрать событие. Под результатами находятся реальные кадры до/в момент/после, окно ±1/3/5 секунд, увеличение и проигрывание контекстного MP4. FFmpeg извлекает их из исходного загруженного файла, не из генератора. Края окна ограничиваются длиной видео. Отметка ≈ означает запрошенное время поиска декодером: точный PTS кадра с плавающей частотой кадров не заявляется.

Для MOV с неподдерживаемым браузером кодеком есть «Совместимый просмотр». Конвертируется копия для просмотра; в модель уходит исходный файл. Скорость и временная шкала сохраняются, звук исключается.

Защищённые вспомогательные маршруты:

| Маршрут | Multipart-поля | Ответ |
|---|---|---|
| `/api/v1/media/info` | `file` | `duration_sec` |
| `/api/v1/media/context` | `file`, `timestamp`, `window` | три JPEG + роли и времена |
| `/api/v1/media/clip` | `file`, `timestamp`, `window` | MP4 с фрагментом |
| `/api/v1/media/variant` | `file`, `kind` | MP4 |

`kind`: original (совместимый просмотр), dark, blur, occlusion. Ограничения медиоинструментов: 100 МБ, до 600 секунд, два одновременных запроса, до 90 секунд на преобразование; временные входы и выходы удаляются после ответа. Вспомогательные пределы не меняют контракт inference для жюри. В ffmpeg разрешены только локальные file/pipe протоколы и MOV/Matroska/WebM демультиплексоры.

## Стенд испытаний

Рабочая станция → Стенд испытаний. Здесь нет демонстрационного распознавания. Каждая запись отправляется в настоящий `/analyze`, затем опрашивается `/jobs`. Модель подключена: запись проходит через настоящий локальный анализ. Ошибки возвращаются явно, проценты качества вычисляются только по заданным человеком эталонам.

1. Добавить свои разрешённые записи как «Независимая запись» или «Другая камера».
2. При желании создать dark/blur/occlusion из выбранного исходника. Перекрытие и размытие могут скрыть наблюдаемое действие: эталон **не наследуется**, его задаёт человек после просмотра.
3. Указать ожидаемый вердикт и, для положительного примера, один эталонный таймкод в секундах. Пустой эталон допустим для технического прогона, но исключается из точности.
4. Запустить последовательно. Кнопка остановки завершает текущую запись и прекращает запуск следующих. Переход на главную сохраняет стенд в текущем сеансе; перезагрузка страницы очищает локальные файлы стенда.
5. Экспортировать JSON: SHA-256 каждого входа, происхождение варианта, ручную разметку, job_id, время, ответы и метрики. Ключей API и видеобайтов в экспорте стенда нет; изображения доказательств заменены количеством.

Независимые записи, подмножество «Другая камера» и производные варианты оцениваются отдельно. Эти три карточки не суммируются. Одинаковые SHA-256 внутри группы исключаются из повторного расчёта точности. Число обработанных записей и ошибки показываются отдельно. Повторный запуск на новом наборе весов: экспортировать текущий сеанс и добавить записи заново/обновить страницу.

Точность = (TP+TN)/(TP+TN+FP+FN) только для завершённых размеченных недемонстрационных результатов. Ошибки обработки исключены из этой дроби, но отражены отдельно, как и покрытие обработки. Ошибка момента — среднее расстояние до ближайшего предсказанного события для одной указанной положительной эталонной отметки; пропуск события учитывается в FN. Это исследовательская метрика, не воспроизведение скрытой системы жюри и не полная оценка всех событий.

Преобразования одного видео не считаются новой камерой и не доказывают перенос на новый ракурс. Для улучшения модели использовать отдельный обучающий материал; собственный отложенный набор не подмешивать в обучение. Видео жюри не использовать для обучения.

## Проверки

`npm run build`, `npm run check:i18n`, `npm run check:features`, `python -m pytest backend -q`. Тесты FFmpeg создают геометрический синтетический ролик; реальные банковские записи для них не требуются. Проверяется работа инструментов, а не качество ещё не подключённой ИИ.

Технические источники: [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html), [imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg). Python-зависимость закреплена на версии 0.6.0. Для поставки в банк проверить лицензию фактически используемой сборки FFmpeg и кодеков.
