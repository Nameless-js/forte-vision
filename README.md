# Forte Vision — локальный видеоанализ кассовых операций

Проект для кейса ForteBank на Datathon 2026: веб-приложение помогает проверяющему находить признаки нарушений кассовой дисциплины на видеозаписи. Пользователь загружает видео и получает вердикт, список событий, таймкоды, кадры-доказательства и ссылки на нормативные основания.

**Основной сценарий для жюри:** клонировать репозиторий → установить зависимости → скачать открытые веса → запустить `scripts/start_app.py` → открыть интерфейс → загрузить своё видео. Обработка выполняется на компьютере, где запущен Python-сервер. Облачный AI API и платный ключ модели не нужны.

В репозитории находятся **и интерфейс, и подключённый движок**. Названия ViBank и BlockWatch относятся к двум оформлениям одного приложения. Реальный анализ включён по умолчанию; демонстрационные события доступны отдельным режимом и не являются результатами модели.

## Что реализовано

- Загрузка MOV, MP4 и WebM размером до **100 МиБ** через браузер или HTTP API.
- Асинхронный анализ: создание задания, отображение этапа/прогресса, получение результата.
- Вердикты `violation` и `no_violation`; отдельный статус `failed` при ошибке.
- События с русским описанием, таймкодом и 1–3 JPEG-кадрами в base64.
- Нормативные карточки из локальной базы: документ, пункт, цитата и URL Adilet. Ссылки прикрепляет код, а не генерирует модель.
- Просмотр видео, переход к событию, контекст события, экспорт JSON и история проверок в SQLite.
- Два оформления интерфейса, интерфейсные переводы ru/kk/en. **Для просмотра реальных описаний модели выберите русский язык:** переводы событий модель не создаёт.
- Один активный анализ на экземпляр сервера. Параллельная загрузка во время анализа получает HTTP 429.
- Изолированный процесс модели с контролем времени и восстановлением после ошибки. Веса остаются загруженными между последовательными заданиями.

| Компонент | Требование / рекомендация |
| --- | --- |
| ОС | Основная проверенная среда — Windows 11 x64. Команды для Linux x86_64 приведены ниже; полная установка на Linux отдельно не проверялась. |
| Python | **3.12 x64**. Метаданные допускают 3.10–3.12; для воспроизведения используйте 3.12. Python 3.13/3.14 не поддерживается текущим набором зависимостей. |

| GPU | Для основного профиля — NVIDIA с **8 ГБ VRAM**, актуальным драйвером и поддержкой CUDA 12.4. Проверено на RTX 4060 Laptop. |
| ОЗУ / диск | Рекомендуется 16 ГБ ОЗУ или больше; ориентировочно 25–30 ГБ свободного диска под окружение, загрузки и веса. Точный объём зависит от профиля и кешей. |
| Интернет | Нужен при установке Python/npm-пакетов и первом скачивании весов. После загрузки весов анализ локальный. |

Отдельная установка CUDA Toolkit обычно не требуется: `scripts/run.py setup` устанавливает PyTorch 2.6.0 / torchvision 0.21.0 с CUDA 12.4 из официального индекса. Драйвер NVIDIA должен быть установлен в системе.

**Для воспроизведения измеренного качества используйте `gpu-small`, даже если у вас более мощная GPU.** Профиль `auto` на GPU от 15 ГБ выбирает `gpu-large`, где другие модели; приведённые ниже метрики к нему не относятся. На CPU VLM отключена: это отдельный облегчённый режим, для него не заявлены те же качество и время. macOS / Apple Silicon в рамках сдачи не проверялись.

## Установка на Windows (PowerShell)

Команды выполняются в **PowerShell**, по очереди. Установите Python 3.12, Node.js и Git заранее. Не требуется активировать виртуальное окружение или менять ExecutionPolicy.

### 1. Проверить инструменты и получить исходники

```powershell
git --version
py -3.12 --version
node --version
npm --version
nvidia-smi

git clone https://github.com/Nameless-js/forte-vision.git
cd forte-vision
```

`nvidia-smi` должен показывать NVIDIA GPU. Все дальнейшие команды, кроме явно указанного `cd frontend`, запускаются из корня `forte-vision`, где находится этот README.

### 2. Установить Python-зависимости

```powershell
py -3.12 scripts/run.py setup
.\.venv\Scripts\python.exe -m pip install -r frontend/backend/requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

`setup` создаёт `.venv`, устанавливает PyTorch, зависимости движка и dev-инструменты. Если доступны `public/` и исходная таблица, пересобирает разметку. В обычном Git-клоне выводится `Dataset not supplied: skipping label rebuild` — это нормально: исходные видео организаторов в Git не входят и **не нужны для анализа своего файла**.

Установка может занимать значительное время из-за PyTorch и ML-библиотек. Переходите дальше только после успешного завершения команды. Если `.venv` уже создавалась другой версией Python, используйте новую копию репозитория с Python 3.12.

### 3. Проверить доступность CUDA

```powershell
.\.venv\Scripts\python.exe -c "import torch; print('torch:', torch.__version__); print('CUDA:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Для основного сценария ожидается `CUDA: True`. Если `False`, сначала исправьте драйвер/установку PyTorch или воспользуйтесь CPU-вариантом ниже.

### 4. Скачать веса один раз

```powershell
.\.venv\Scripts\python.exe scripts/download_weights.py --profile gpu-small
```

Загружаются Grounding DINO tiny, RTMPose и Qwen3-VL-4B-Instruct. Дождитесь `all weights downloaded`. Файлы Hugging Face сохраняются в `models/hf/`, ONNX-файлы RTMPose — в пользовательском кеше `~/.cache/rtmlib`. Загрузка модели не означает обучение. Веса не включены в репозиторий.

### 5. Установить интерфейс и запустить

```powershell
cd frontend
npm ci
cd ..
$env:FORTE_PROFILE = "gpu-small"
.\.venv\Scripts\python.exe scripts/start_app.py
```

Оставьте терминал открытым. После сообщений о готовности откройте **http://127.0.0.1:5173**.

- Интерфейс: **http://127.0.0.1:5173**.
- API Base URL: **http://127.0.0.1:8000**.
- Состояние API: **http://127.0.0.1:8000/api/health**.
- Swagger: **http://127.0.0.1:8000/docs**.
- Остановка обоих серверов и процесса модели: **Ctrl+C** в терминале запуска.

Первый запуск создаёт `frontend/.env` с индивидуальным API-ключом, SQLite и профилем `auto`. Указанная выше переменная `FORTE_PROFILE` имеет приоритет над файлом. Для постоянного выбора профиля замените строку в `frontend/.env` на `FORTE_PROFILE=gpu-small`. Готовый `.env` в Git не публикуется.

### Вариант без NVIDIA GPU

При первой установке замените команду `setup` на `setup --cpu`; после неё выполните остальные шаги установки, используя CPU-профиль:

```powershell
py -3.12 scripts/run.py setup --cpu
.\.venv\Scripts\python.exe -m pip install -r frontend/backend/requirements.txt
.\.venv\Scripts\python.exe scripts/download_weights.py --profile cpu
cd frontend
npm ci
cd ..
$env:FORTE_PROFILE = "cpu"
.\.venv\Scripts\python.exe scripts/start_app.py
```

В этом режиме используются CPU-детектор и поза, VLM отключена. На медленном CPU видео может не уложиться в лимит веб-анализа. Это не эквивалент GPU-результатов.

## Установка на Linux (Bash)

Нужны Python 3.12 с модулем `venv`, Git, Node.js/npm и для основного сценария драйвер NVIDIA. Пример для Ubuntu с уже доступным Python 3.12:

```bash
sudo apt-get update
sudo apt-get install -y git python3.12-venv libgl1 libglib2.0-0
python3.12 --version
node --version
npm --version
nvidia-smi

git clone https://github.com/Nameless-js/forte-vision.git
cd forte-vision
python3.12 scripts/run.py setup
./.venv/bin/python -m pip install -r frontend/backend/requirements.txt
./.venv/bin/python -m pip check
./.venv/bin/python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
./.venv/bin/python scripts/download_weights.py --profile gpu-small
cd frontend
npm ci
cd ..
FORTE_PROFILE=gpu-small ./.venv/bin/python scripts/start_app.py
```

Откройте http://127.0.0.1:5173. Для CPU используйте `setup --cpu`, скачивание `--profile cpu` и запуск `FORTE_PROFILE=cpu`. Наличие пакета `python3.12-venv` зависит от версии дистрибутива; системный Python не нужно заменять. Команды Linux приведены по реализации скриптов, отдельный полный прогон на Linux не выполнялся.

## Повторный запуск

Установка зависимостей и скачивание весов нужны один раз. В новом терминале:

Windows:

```powershell
cd ПУТЬ_К_РЕПОЗИТОРИЮ\forte-vision
$env:FORTE_PROFILE = "gpu-small"
.\.venv\Scripts\python.exe scripts/start_app.py
```

Linux:

```bash
cd /path/to/forte-vision
FORTE_PROFILE=gpu-small ./.venv/bin/python scripts/start_app.py
```

Если профиль уже сохранён в `frontend/.env`, устанавливать переменную каждый раз не нужно. Для CPU подставьте `cpu`. Отдельный `server.worker`, Supabase, Docker и второй ручной запуск Vite для этого сценария не требуются.

Если порты заняты:

```powershell
.\.venv\Scripts\python.exe scripts/start_app.py --port 5174 --api-port 8001
```

В этом случае интерфейс будет на 5174, API на 8001; прокси настроится автоматически.

## Проверка через интерфейс

1. Откройте http://127.0.0.1:5173 и выберите **русский язык**.
2. Откройте рабочую станцию / загрузку видео. Можно пользоваться любым из двух оформлений.
3. Выберите настоящий файл MOV, MP4 или WebM до 100 МиБ. Папка `public/` для этого не нужна.
4. Запустите анализ, оставив демонстрационный режим выключенным.
5. Дождитесь результата. Первый анализ дополнительно загружает модели в память; проверка `/api/health` сама по себе модели не загружает.
6. Проверьте вердикт, список событий, переход по таймкоду, JPEG-кадры и нормативное основание. При `no_violation` список событий пуст.
7. Экспортируйте JSON. Выполненную проверку можно найти в истории.

При запуске через `start_app.py` ключ в браузере вводить не нужно: Vite добавляет его к запросам на своей серверной стороне. История хранится в `frontend/runtime/jobs.sqlite`. Загруженный для анализа файл удаляется после обработки; результат, включая JPEG-кадры, остаётся в локальной базе. После перезапуска страницы для медиапросмотра может понадобиться повторно выбрать исходный файл.

Кнопка демонстрации служит только для знакомства с интерфейсом. Поле `demo: true` обозначает учебный результат; его нельзя использовать для оценки модели.

## API и ключ для жюри

### Адрес и авторизация

Для локального запуска:

```text
API Base URL: http://127.0.0.1:8000
Header name: X-API-Key
```

Base URL указывается **без** `/api/v1/analyze`; полный путь загрузки — `http://127.0.0.1:8000/api/v1/analyze`.

API-ключ создаётся при первом запуске в `frontend/.env`. Посмотреть его на своей машине:

```powershell
Get-Content frontend/.env | Select-String '^API_KEY='
```

Linux:

```bash
sed -n 's/^API_KEY=//p' frontend/.env
```

В поле ключа передаётся только значение после `API_KEY=`, без кавычек. Если вы задавали `API_KEY` через переменные окружения, используется оно; файл приоритетнее не становится. Если ключ отсутствует и в окружении, и в `.env`, резервный ключ находится в `frontend/runtime/.api-key`.

**Для внешнего жюри `127.0.0.1` не является публичным адресом.** Каждый проверяющий может запустить проект локально и получить свой ключ. Для проверки вашего работающего сервера по сети нужно отдельно предоставить публичный HTTPS URL и приватно передать ключ этого экземпляра. Публичный хостинг/туннель в этом репозитории не настроен. Приватный действующий ключ намеренно не записан в README.

### Основные маршруты

| Метод и путь | Авторизация | Назначение |
| --- | --- | --- |
| `GET /api/health` | Нет | Сервер и подключение к хранилищу; не подтверждает готовность GPU/весов. |
| `POST /api/v1/analyze` | `X-API-Key` | Multipart-поле `file`; HTTP 202 и `job_id`. |
| `GET /api/v1/jobs/{job_id}` | `X-API-Key` | Статус, прогресс, результат или ошибка. |
| `GET /api/v1/jobs?limit=30` | `X-API-Key` | История, до 100 заданий за запрос. |
| `POST /api/v1/demo/jobs` | `X-API-Key` | Учебные события; не запускает модель. |
| `/api/v1/media/*` | `X-API-Key` | Метаданные, контекст, фрагменты и преобразования видео для интерфейса. |
| `GET /docs` | Нет | Интерактивная схема всех HTTP-маршрутов. |

Ошибки загрузки: `400` — пустой файл; `401` — неверный ключ; `413` — больше 100 МиБ; `415` — неподдерживаемое расширение; `429` — анализатор занят. Неизвестное задание возвращает `404`. Ошибка модели после принятия загрузки возвращается через статус задания `failed`, поле `error`.

### Пример запроса из PowerShell

Выполните во **втором** терминале из корня репозитория, пока приложение работает. Пример использует `curl.exe`, чтобы избежать PowerShell-псевдонима `curl`:

```powershell
$baseUrl = "http://127.0.0.1:8000"
$juryKey = (Get-Content frontend/.env | Where-Object { $_ -match '^API_KEY=' } | Select-Object -First 1) -replace '^API_KEY=', ''
$videoPath = "C:\Videos\example.mp4"

curl.exe --fail-with-body "$baseUrl/api/health"
$job = curl.exe --fail-with-body -s -H "X-API-Key: $juryKey" -F "file=@$videoPath" "$baseUrl/api/v1/analyze" | ConvertFrom-Json
$job.job_id

# Повторяйте запрос до status=done или status=failed.
curl.exe --fail-with-body -H "X-API-Key: $juryKey" "$baseUrl/api/v1/jobs/$($job.job_id)"
```

Поменяйте `C:\Videos\example.mp4` на существующий файл. Если API_KEY переопределён переменной окружения, подставьте это значение в `$juryKey`.

Linux / Bash:

```bash
BASE_URL=http://127.0.0.1:8000
JURY_KEY=$(sed -n 's/^API_KEY=//p' frontend/.env | tr -d '\r')
curl --fail-with-body "$BASE_URL/api/health"
curl --fail-with-body -H "X-API-Key: $JURY_KEY" -F 'file=@/path/to/example.mp4' "$BASE_URL/api/v1/analyze"
# Скопируйте job_id из ответа:
curl --fail-with-body -H "X-API-Key: $JURY_KEY" "$BASE_URL/api/v1/jobs/ЗАМЕНИТЕ_НА_JOB_ID"
```

Ответ на загрузку:

```json
{"job_id": "UUID-задания"}
```

Во время обработки:

```json
{"job_id": "UUID-задания", "status": "processing", "progress": 0.45, "stage": "Название этапа", "violations": []}
```

Завершённый ответ содержит `status: "done"`, `verdict`, `violations`, сведения о видео и длительности обработки. У события есть `type`, `type_id`, `description`, `timecode_sec`, `confidence`, `evidence_frames` и нормативная карточка `rule`. `image_base64` — чистый base64 JPEG без префикса `data:`. Веб-адаптер сохраняет `rule.document` / `rule.clause` и добавляет `rule.title` / `rule.section` для интерфейса. При ошибке `status: "failed"` — это **не** вердикт об отсутствии нарушения. Полная схема успешного результата: [forte_ai/result_schema.json](forte_ai/result_schema.json).

### Один порт для собранного интерфейса и API

Основной проверенный сценарий выше использует Vite. Для запуска собранного интерфейса:

```powershell
cd frontend
npm run build
cd ..
$env:FORTE_PROFILE = "gpu-small"
.\.venv\Scripts\python.exe -m uvicorn frontend.backend.main:app --host 127.0.0.1 --port 8000
```

Предварительно завершите `start_app.py`, чтобы освободить порт. Откройте http://127.0.0.1:8000. В этом варианте в панели «Подключение» интерфейса **нужно ввести API-ключ**: Vite-прокси больше не участвует. Backend читает `frontend/.env` сам. Если его ещё нет, ключ будет создан в `frontend/runtime/.api-key`.

Для доступа с другого компьютера в своей сети можно слушать `--host 0.0.0.0` и использовать реальный IP хоста; доступ зависит от настроек сети и firewall. Это само по себе не создаёт публичный HTTPS URL. Корневой Dockerfile предназначен для отдельного референсного API движка, не для полного веб-приложения; сборка Docker не проверена.

## Как работает модель

```text
React / Vite
    → FastAPI: загрузка, API-ключ, задания, SQLite, медиасервис
    → frontend/backend/model_adapter.py
    → SupervisedAnalyzer: отдельный постоянный процесс и контроль времени
    → forte_ai.Analyzer
        → декодирование и выборка кадров
        → Grounding DINO: люди, наличные, документы, предметы и оборудование
        → трекинг ByteTrack и RTMPose: траектории и геометрия позы
        → оценка ролей и зон: кассир, клиент, посетители
        → временные правила: кандидаты событий
        → локальная VLM: контрастная оценка A/B и описание
        → порог уверенности, JPEG-доказательства и нормативная карточка
    → результат задания → интерфейс / JSON
```

Это гибридная система из предобученных открытых моделей, собственной логики ролей/событий, порогов и локальной нормативной базы. Собственные дообученные нейросетевые веса не заявляются. Система не выполняет установление личности по лицу и не подтверждает фактические полномочия человека по системам доступа.

В измеренном профиле `gpu-small` используются **IDEA-Research/grounding-dino-tiny**, **RTMPose lightweight** и **Qwen/Qwen3-VL-4B-Instruct** с 4-битной NF4-квантизацией языковой части. Настройки находятся в `configs/default.yaml` и `configs/profile-gpu-small.yaml`.

Среди сценариев: приём/выдача без видимого пересчёта, оставление рабочего места/ценностей, посторонние в зоне кассира, пересечение операций двух клиентов, передача без видимых документов, непроверенная инкассаторская сумка, личные вещи. Наличие правила не доказывает одинаковое качество на всех типах. Экспериментальный VLM catch-all выключен; распознавание любого неизвестного нарушения не гарантируется. Подробная таксономия: [VIOLATION_TYPES.md](VIOLATION_TYPES.md).

Бюджет движка — 240 с, жёсткий лимит дочернего процесса веб-адаптера — 250 с, внешний тайм-аут backend — 270 с. При превышении возвращается ошибка, процесс закрывается; следующий запрос может создать его заново. Прямой CLI использует `Analyzer` с мягким бюджетом, а не эту же процессную защиту.

### Хранение и настройки

| Путь / переменная | Назначение |
| --- | --- |
| `frontend/.env` | Локальные настройки, индивидуальный `API_KEY`; исключён из Git. |
| `FORTE_PROFILE` | `gpu-small`, `gpu-large`, `cpu` или `auto`. Переменные окружения имеют приоритет над `.env`. |
| `FORTE_CONFIG` | Необязательный путь к YAML с переопределениями движка. |
| `FORTE_MODELS_DIR` | Каталог моделей Hugging Face, по умолчанию `models/hf`. Сохраняйте одинаковое значение при скачивании и запуске. |
| `FORTE_CACHE_DIR` | Каталог кеша движка, по умолчанию `data/cache`. |
| `DATA_DIRECTORY` | Каталог загрузок/истории backend, по умолчанию `frontend/runtime`. |
| `DATABASE_BACKEND` | По умолчанию `sqlite`. Supabase опционален; для локального запуска не нужен. |
| `models/hf/`, `~/.cache/rtmlib` | Локальные веса; в Git отсутствуют. |

Для принудительного офлайн-режима после скачивания всех весов можно установить `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Перенос только `models/hf` на другой компьютер недостаточен для RTMPose: понадобится также его пользовательский ONNX-кеш либо повторная загрузка скриптом.

## Измеренные результаты и ограничения

Проверенная среда: Windows 11, RTX 4060 Laptop 8 ГБ, PyTorch 2.6.0+cu124, профиль `gpu-small`. На открытом наборе — 42 размеченных видео: 22 с нарушением и 20 без; после объединения дубликатов — 40 групп.

| Оценка | Найдено положительных | Ложные тревоги | Accuracy |
| --- | --- | --- | --- |
| Текущий порог конфигурации 0.5, открытый набор | 17 / 22 | 1 / 20 | 85.7% |
| LOVO с подбором порога внутри фолда | 17 / 22 | 2 / 20 | 83.3% |

LOVO здесь переподбирает пороги. Правила, подсказки и таксономия разрабатывались на открытом наборе, поэтому это **не независимая оценка всей системы на невидимых данных**. Точность типа 71%, локализация в ±2 с — 59%; обе оценки условны на обнаруженных положительных видео. Пропуски в их знаменатель не входят.

Три холодных измерения без кеша результатов: **110.7 / 61.8 / 70.2 с**. Прогон реального видео 4 через интерфейсный прокси → API → модель занял **29.0 с** в подготовленном окружении; он не является обещанием времени для произвольного файла или чистого компьютера. Проверка устойчивости ограничена 12 из 378 вариантов: совпадение вердикта 83.3%; полный набор не завершён.

Качество ограничено размером мелких объектов, ракурсом, перекрытиями, отражениями, видимостью рук/сейфа и неоднозначностью ролей. Невидимое действие не доказывает его отсутствие. Юридический вывод и окончательное решение остаются за проверяющим. Строгие внутренние цели обнаружения, локализации и классификации пока не достигнуты.

Подробности: [FINAL_REPORT.md](FINAL_REPORT.md), [LIMITATIONS.md](LIMITATIONS.md), [reports/integration/report.json](reports/integration/report.json). Отчёт FINAL_REPORT фиксирует инженерную оценку движка до интеграции UI; результаты интеграции приведены отдельно. Установка всех зависимостей с нуля на чужой машине и внешний публичный сервис отдельно не подтверждены.

```powershell
cd frontend
```

Зафиксированный совместный набор: **140 прошедших тестов**; сборка TypeScript/Vite и проверки переводов/функций проходили. Эти тесты не требуют исходных видео для запуска модели и не заменяют оценку ML-качества.

### Проверка реальной модели на своём видео без браузера

```powershell
.\.venv\Scripts\python.exe -m forte_ai analyze "C:\Videos\example.mp4" --profile gpu-small --out tmp/result.json --evidence-dir tmp/evidence
```

Не запускайте CLI и веб-анализ одновременно на одной 8-ГБ GPU. Веса должны быть скачаны заранее. Для Linux замените интерпретатор на `./.venv/bin/python` и путь к файлу на Linux-путь.

### Воспроизведение измерений на видео организаторов

Исходные видео не распространяются в Git. Поместите предоставленные организаторами файлы с исходными именами в `public/` в корне проекта; таблица `open/open_labels.xlsx` уже находится в репозитории. Затем:

```powershell
.\.venv\Scripts\python.exe scripts/build_labels.py
$env:FORTE_PROFILE = "gpu-small"
.\.venv\Scripts\python.exe scripts/check_app.py
```

`check_app.py` использует **видео 4** из таблицы разметки, порты 5174 и 8013, настоящий движок без моков; записывает результат в `reports/integration/`. Он не предназначен для Git-клона без предоставленного набора видео. Скрипт запускает и останавливает собственные серверы.

Полная инженерная проверка:

```powershell
.\.venv\Scripts\python.exe scripts/run.py verify
.\.venv\Scripts\python.exe scripts/run.py verify --resume
```

Полный прогон включает 378 преобразований и может занимать часы. Он не нужен для обычного запуска. Пока внутренние цели качества не достигнуты, `verify` и `scripts/final_report.py --check` ожидаемо завершаются ненулевым кодом; это не означает, что веб-сервер не запускается. `--resume` переиспользует успешно завершённые этапы при совпадении хеша исходников.

## Решение проблем

| Симптом | Что проверить |
| --- | --- |
| `py -3.12` не найден | Установите Python 3.12 x64 с Python Launcher; откройте новый PowerShell. |
| PowerShell запрещает `npm.ps1` | Используйте `npm.cmd ci` / `npm.cmd run build`; активация Python-окружения не нужна. |
| `No matching distribution found` / ошибка установки | Проверьте Python 3.12 x64 и полный лог первой упавшей команды. Не используйте частично установленное окружение как готовое. |
| `No module named dotenv` / `fastapi` | Выполните установку `frontend/backend/requirements.txt` через `.venv`, затем запускайте именно `.venv`-интерпретатор. |
| `CUDA: False` | Проверьте `nvidia-smi`, драйвер и наличие CUDA-сборки PyTorch. Если выбрали `setup --cpu`, CUDA отключена намеренно. |
| Нет весов / ошибка Hugging Face offline | Повторите `download_weights.py --profile gpu-small` с интернетом. Профиль скачивания и запуска должен совпадать. |
| Ошибка загрузки RTMPose без интернета | Выполните загрузку весов под тем же пользователем ОС; ONNX-кеш лежит в домашнем каталоге пользователя. |
| `CUDA out of memory` | Завершите другие GPU-задачи, оставьте один анализ. Используйте `gpu-small`; для CPU переключите и веса, и профиль запуска. |
| Порт 5173 или 8000 занят | Остановите прошлую копию Ctrl+C либо используйте `--port 5174 --api-port 8001`. |
| `Install frontend dependencies first` | Выполните `npm ci` именно в `frontend/`; проверьте `node --version`. |
| Ошибка соединения в браузере | Запускайте весь проект через `scripts/start_app.py`, оставьте терминал открытым и проверьте `/api/health`. |
| HTTP 401 | При прямом обращении используйте `X-API-Key` данного экземпляра. После замены ключа перезапустите серверы. |
| HTTP 429 | Дождитесь завершения текущего анализа и повторите загрузку. Очередь нескольких видео не реализована. |
| Видео не воспроизводится в браузере | Попробуйте функцию подготовки превью / MP4 H.264. Декодирование движком и браузерное воспроизведение — разные операции. |
| Задание `failed` / тайм-аут | Прочитайте `error` через API и лог терминала; проверьте веса, GPU и длительность видео. Это не `no_violation`. |
| На kk/en написано «Нет перевода» | Выберите русский: автоматический перевод реальных описаний не реализован. |
| Отсутствуют `public/*.mov` | Для своей загрузки это нормально. Для eval/check_app нужен исходный набор организаторов. |

Системный `ffmpeg` для стандартного медиасценария не обязателен: используется бинарник из `imageio-ffmpeg`. Для диагностики сохраняйте лог ошибки без API-ключа и не добавляйте `.env`, пользовательские видео или SQLite в коммиты.

```text
frontend/
  src/                  React/TypeScript: интерфейс, плеер, события, переводы
  public/fonts/         локальные шрифты интерфейса
  backend/
    main.py             интегрированный FastAPI API и жизненный цикл заданий

  .env.example          пример переменных; не готовый секрет
forte_ai/
  analyzer.py           основной конвейер анализа
  supervisor.py         процессная изоляция и ограничение времени
  perception/           детектор, трекинг, поза
  events/               временная логика событий
  vlm/                  локальная мультимодальная модель
  result_schema.json    схема результата
configs/                настройки и профили оборудования
kb/                     нормативные тексты и карточки правил
```

В Git включены исходники, npm lockfile, локальные шрифты, конфигурация, нормативная база и отчёты без встроенных кадров. Не включены `.venv`, `node_modules`, веса, исходные видео, кеши, базы истории и действующие ключи.
