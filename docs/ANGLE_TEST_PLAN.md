# План проверки ракурсов и демонстрации

## Что подготовить команде

Снять собственные постановочные короткие записи разрешённых сцен: корректное действие и наблюдаемая проблемная ситуация, для каждой — исходная камера, смещённая камера, боковая камера. Получится минимум шесть записей, а не шесть преобразований одного файла. Не использовать идентификацию лиц и звук. Тип события и нормативное объяснение заранее сверить с найденными источниками; этот план сам не устанавливает юридических нарушений.

Для каждого ролика два человека независимо отмечают вердикт, наблюдаемое действие и момент. Разногласия разрешают просмотром контекста, а не ответом модели. Если по новому ракурсу действие неразличимо, зафиксировать ограничение и не наследовать положительную метку автоматически. Для стенда допускается неразмеченная запись; она не входит в точность.

Сохранять однотипные действия в одной группе при разделении обучения и проверки. Синтетические изменения и дубли одного исходника должны оставаться в той же группе, иначе получится утечка между обучением и тестом.

## Порядок прогона

1. Зафиксировать версию весов и набор правил в своей рабочей записи.
2. Загрузить исходные отложенные записи в стенд, отдельно пометить записи с другой камеры.
3. Ввести эталоны. Сохранить экспорт с SHA-256, чтобы не подменить файлы между сравнениями.
4. Запустить реальные задания. Зафиксировать успешные ответы, ошибки, ложные тревоги, пропуски, время и ошибку момента.
5. Создать по одному варианту dark/blur/occlusion и просмотреть их. Эталоны назначить заново по видимости действия.
6. Найденные ошибки оформить как ограничения. Изменения модели проверять на новом отложенном наборе; не выдавать запомненный тест за независимую проверку.

## Демонстрация за 90 секунд

- 0–20 с: загрузить разрешённую запись, показать настоящий ответ локальной модели и таймкод. Для презентации можно заранее открыть завершённый результат, честно сообщив время обработки.
- 20–45 с: выбрать событие, показать до/момент/после и проиграть фрагмент; увеличить релевантный кадр.
- 45–65 с: открыть наблюдения, показать возможное альтернативное объяснение и отдельную отметку проверяющего. Если модель не возвращает checks, прямо показать «не установлено».
- 65–90 с: показать стенд на независимой другой камере, реальные FN/FP и ограничения. Не обещать качество, которого измерения не подтвердили.

## Текущая готовность

Восстановление и преобразования работают без ИИ. Наблюдения модели готовы к приёму, но их получение должен реализовать ML-модуль. Стенд исполняет реальные API-задания; до подключения ML-адаптера показывает ошибку отсутствующей модели. Оценка точности модели и устойчивости к ракурсам пока не проведена.
